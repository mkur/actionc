# MIR6502 Aggregate-Copy and Narrow-Result Optimization Plan

Snapshot date: 2026-09-02.

Status: in progress; Slices 1-3 implemented.

This plan addresses the general MIR6502 code-generation problems exposed by
`samples/demoscene/unlimited-bobs.act::SelectEffect`. `SelectEffect` is a
measurement case, not an optimization contract: no implementation may depend
on its routine name, record name, field offsets, table length, constants, or
source spelling.

The implementation order is:

```text
retain aggregate-copy identity into MIR6502
    -> evaluate each effective copy address once
    -> strength-reduce constant address scales
    -> narrow a discarded-high constant product
    -> measure and consider a bounded compact-copy follow-up
```

Each required slice is independently useful and should be committed before the
next slice begins.

## Baseline

The motivating Action! source performs a twelve-byte indexed record copy and
then derives four byte steps:

```action
currentParams=effectTable(effect)
bobStepXA=BASE_LANE_STEP*currentParams.bobHarmonicXA
bobStepXB=BASE_LANE_STEP*currentParams.bobHarmonicXB
bobStepYA=BASE_LANE_STEP*currentParams.bobHarmonicYA
bobStepYB=BASE_LANE_STEP*currentParams.bobHarmonicYB
```

Optimized NIR is already compact and target-independent:

```text
copy_bytes currentParams = effectTable[effect;12] size=12
```

Current MIR6502 lowering expands that operation into twelve independent
computed-index loads followed by twelve stores. Materialization subsequently
rebuilds `effectTable + effect * 12` for every load. The emitted routine is
2,448 bytes:

| Region | Current size | Share of routine |
|---|---:|---:|
| Indexed record copy | 2,211 bytes | 90.3% |
| Four multiply/truncate expressions | 237 bytes | 9.7% |

The copy performs twelve scaled address calculations. Each scale-twelve
calculation is emitted as twelve 16-bit additions, producing 144 word additions
for one twelve-byte record assignment. Those additions alone account for about
1,872 code bytes.

The comparison Mad Pascal translation uses an explicitly packed byte table,
computes the selected row address once, calls its shared `Move`, and emits five
`ASL` instructions for each multiply-by-32. Its `SelectEffect` body is 91 bytes.
The source constructs are not identical because Mad Pascal 1.7.9 cannot declare
the original array of records, so that number is a quality signal rather than
an exact regression target.

`SelectEffect` runs once per twenty-second effect slot, before the much larger
screen clear. This work is therefore primarily about executable size, general
aggregate-copy quality, and zero-page pressure rather than steady-state frame
speed.

## Diagnosis

There are three independent target problems.

### Aggregate identity is discarded too early

`NirOp::CopyBytes` contains the facts needed by target selection: two complete
addressable places, a verified extent, source/destination volatility, single
address evaluation, and overlap-safe value semantics. `mir6502::lower`
immediately scalarizes it into generated byte temporaries. Later passes can see
only unrelated loads and stores and would have to reconstruct the aggregate
operation and its safety contract.

### Computed addresses are materialized per consumer

The twelve source loads retain equal `base`, `index`, and `elem_size` values,
but each `MirAddr::ComputedIndex` or `MirAddr::PointerIndex` consumer receives
an independent pointer preparation. This changes a naturally linear copy into
code whose size is proportional to `copy_size * address_scale`.

### A dead product high lane is still maintained

Action! integer multiplication has a 16-bit semantic result. The four
expressions therefore reach MIR6502 as word multiplication followed by explicit
truncation to byte. Constant multiplication is correctly strength-reduced, but
it performs five full 16-bit shifts even though the only consumer discards the
high byte. The desired low byte is simply the product modulo 256.

## Goals

- Keep NIR unchanged: `CopyBytes` remains the target-independent aggregate-copy
  contract.
- Preserve aggregate identity until MIR6502 has selected a target strategy.
- Evaluate each source and destination effective address exactly once, in the
  source-defined order.
- Preserve self-copy and arbitrary partial-overlap value semantics.
- Preserve volatile read/write counts and ordering barriers.
- Reduce a run of adjacent indexed aggregate loads to one prepared effective
  address plus consecutive byte reads.
- Replace repeated-add address scaling with a costed constant shift/add plan.
- Compute only the low byte of a word product when exact use/liveness facts
  prove that the high lane is unobservable.
- Improve general record assignment, descriptor-backed arrays, scaled indexes,
  and byte-truncated arithmetic without recognizing a sample program.
- Leave verifier-clean MIR at every phase boundary and make the selected and
  rejected paths visible through peephole statistics.

## Non-goals

- Do not change Action! record-assignment, integer-promotion, or truncation
  semantics.
- Do not add 6502 locations or addressing modes to NIR.
- Do not make MIR6502 consult SemIR or source text.
- Do not introduce general alias analysis, interprocedural range propagation,
  or bounds inference.
- Do not assume a mutable array descriptor still points at its initializer
  backing.
- Do not replace an arbitrary record copy with the forward-only
  `SYS.MoveBlock` helper.
- Do not reorder, merge, or remove volatile byte accesses.
- Do not add a benchmark-specific field-copy or multiply-by-32 special case.
- Do not require a compact stack-staged copy in the initial implementation;
  address reuse delivers the dominant improvement while retaining the current
  conservative staging model.

## Architectural decisions

### Preserve `CopyBytes` as a pre-home MIR operation

Add a pre-home-only `MirOp::CopyBytes` carrying lowered MIR addresses:

```rust
CopyBytes {
    destination: MirAddr,
    source: MirAddr,
    size: u16,
    destination_volatile: bool,
    source_volatile: bool,
}
```

This does not move source semantics into MIR6502. SemIR still decides whether
the assignment is legal, NIR still defines complete overlap-safe value-copy
semantics, and MIR6502 merely retains the operation until it can choose a 6502
strategy.

The operation is legal only before target copy selection. The post-home
verifier must reject it, and emission must never receive it. Unsupported or
unprofitable candidates use a correctness-first scalar fallback equivalent to
the current all-loads-before-all-stores expansion.

Retaining the operation is preferable to a late peephole over 24 or more scalar
operations: the late form has lost reliable aggregate provenance and forces a
local matcher to rediscover overlap, volatility, extent, and address-evaluation
facts.

### Keep overlap safety independent of alias proof

The first selected strategy still performs every source read before the first
destination write. It may share prepared addresses, byte homes, and index
state, but must not turn the operation into an interleaved load/store loop.

A later selector may use a directional loop or a forward helper only when
structured MIR storage facts prove disjoint ranges or a safe direction. A
pointer-backed source with no exact points-to fact is not disjoint merely
because its descriptor and the destination have different global IDs.

### Perform target selection before emission

The choice between direct bytes, a prepared indirect consumer, scalar staging,
and any later compact copy belongs to MIR6502 materialization. Emission writes
the selected operations and does not discover equal addresses or choose an
optimization based on final instruction text.

### Use exact lane liveness for narrowing

Narrowing a word multiplication is legal only when routine-aware use/def and
lane-liveness facts prove that the high result lane has no observable consumer.
Local adjacency alone is insufficient because a synthetic high lane may be
used later by a compare, call, store, or block terminator.

## Shared safety invariants

- Source and destination address-producing expressions retain their NIR-defined
  evaluation order and execute exactly once.
- Every copied source byte is read exactly once before any destination byte is
  written.
- Every destination byte is written exactly once.
- Self-copy and partial overlap produce the source value as it existed before
  the first destination write.
- Source and destination volatile phases retain explicit barriers. A selector
  that cannot preserve volatile access order must reject the operation.
- Calls, machine blocks, opaque effects, and writes that may change a prepared
  pointer or index end the address-reuse region.
- Prepared pointer pairs and any Y carrier remain unchanged until their last
  consumer.
- Address scale arithmetic is full 16-bit wrapping arithmetic; no selector may
  assume that a byte index is within the declared array bound.
- Low-result multiplication narrowing preserves the result modulo 256 for all
  256 byte inputs and must not remove an observable operand read.
- All rewrites use transactional routine-aware plans, declare A/X/Y/flag exit
  changes, and win the MIR6502 cost model.

## Slice 1 (complete): retain aggregate-copy identity in MIR6502

### Goal

Lower verified NIR `CopyBytes` one-to-one into a pre-home MIR operation instead
of immediately expanding it into scalar byte operations.

### Implementation

1. Add `MirOp::CopyBytes` and printer support in `src/mir6502/ir.rs` and
   `src/mir6502/printer.rs`.
2. Change `src/mir6502/lower.rs` to lower the two places once and retain the
   extent and volatile flags.
3. Teach pre-home use/def, effects, temp-width, storage-reference, machine-value,
   standalone-root, and rewrite visitors about address inputs and conservative
   memory effects.
4. Extend the verifier with phase-aware rules:
   - nonzero extent;
   - valid source and destination addresses;
   - no arithmetic overflow in constant offsets plus extent;
   - legal in initial/pre-home MIR;
   - rejected at the post-home and emission boundaries.
5. Add one explicit scalar fallback expansion before home selection. It creates
   all source byte temps first and emits all destination stores afterward,
   retaining the current overlap-safe behavior.
6. Add statistics for `aggregate-copy-retained` and
   `aggregate-copy-scalar-fallback`.
7. Update the whole-record-copy sections of
   `MIR6502_PSEUDO_MACHINE_CONTRACT.md` and
   `RECORD_INITIALIZERS_AND_ASSIGNMENT_IMPLEMENTATION_NOTE.md`.

### Tests

- Add `fixtures/mir6502/indexed_record_copy.act` with a nontrivial record size
  and dynamic byte index.
- Assert that initial MIR contains one `copy_bytes`, not twelve unrelated
  source expressions.
- Keep `fixtures/runtime/record_assignment.act` green in every public compiler
  mode and runtime.
- Cover direct-to-direct, indexed-to-direct, self-copy, and partial-overlap
  cases.
- Add negative verifier tests proving that pre-home `CopyBytes` cannot reach
  post-home MIR.

### Acceptance criteria

- NIR fixtures are unchanged.
- Initial MIR retains one explicit aggregate copy.
- The fallback produces the same observable operation ordering as the current
  lowering.
- Emitted XEX remains byte-identical for the focused fallback fixtures where
  temporary numbering does not affect layout; any unavoidable difference must
  be explained as target-IR plumbing rather than an optimization.

### Suggested commit

```text
mir6502: retain aggregate copies through target selection
```

## Slice 2 (complete): prepare indexed copy addresses once

### Goal

Select a correctness-first scalar copy whose effective source and destination
addresses are each prepared once and shared by all byte consumers.

### Implementation

1. Add an aggregate-copy selector under `src/mir6502/materialize/`, preferably
   in a focused `copies.rs` module.
2. For `Direct` endpoints, retain direct byte loads/stores with constant
   offsets.
3. For `ComputedIndex` and `PointerIndex` endpoints:
   - snapshot the base and index inputs once, in the endpoint-evaluation order
     recorded by NIR lowering;
   - emit one `MaterializeIndexedAddress` into an eligible pointer consumer;
   - issue consecutive `LoadIndirect` or `StoreIndirect` operations through
     that consumer;
   - retain two prepared consumers when both effective addresses must be fixed
     before the source-read phase;
   - defer destination pointer preparation until after source staging only when
     every destination address input has already been snapped and the deferred
     preparation performs no further observable read.
4. Continue to stage one generated byte value per source lane and emit every
   source read before every destination write. This deliberately avoids adding
   alias assumptions in this slice.
5. Preserve source and destination volatile barriers around their complete
   phases. Reject any address form whose evaluation or pointer lifetime cannot
   be represented exactly.
6. Fall back to Slice 1's scalar expansion for unsupported forms.
7. Record applied and blocked reasons, including volatile-order, unsupported
   address form, unavailable pointer pair, offset range, and cost rejection.

### Tests

- Dynamic byte- and word-indexed record arrays.
- Element sizes 1, 2, 3, 12, and a value large enough to cross a page.
- A pointer-backed source whose descriptor cannot be assumed constant.
- Computed destinations as well as computed sources.
- Self-copy and leftward/rightward partial overlap.
- Source-volatile, destination-volatile, and both-volatile copies, checking
  exact access count and ordering.
- Calls, machine blocks, or opaque barriers adjacent to the copy must not be
  crossed by preparation or reuse.

### Acceptance criteria

- The motivating twelve-byte copy contains one source pointer preparation and
  one scale-twelve advance, not twelve of each.
- The materialized MIR contains twelve byte reads followed by twelve byte
  writes, with no interleaving.
- No source descriptor, base value, or index is reloaded solely for the next
  field offset.
- The record-copy portion of `SelectEffect` is reduced by at least 70% in the
  measurement build. This measurement is reported, not encoded as a brittle
  byte-count unit test.
- Runtime overlap and volatile fixtures remain exact.

### Suggested commit

```text
mir6502: reuse prepared addresses for aggregate copies
```

## Slice 3 (complete): strength-reduce constant address scales

### Goal

Replace `scale` repeated 16-bit additions in indexed-address preparation with a
costed shift/add calculation whose work grows with the constant's bit pattern,
not its numeric value.

### Implementation

1. Add a target-local constant-scale planner to the `AdvanceAddress` encoding
   path in `src/mir6502/emit.rs`. `AdvanceAddress` is already the explicit
   MIR6502-selected target operation; this planner chooses its instruction
   encoding and does not reconstruct source semantics.
2. Model these legal strategies:
   - no work for scale one;
   - shifts for powers of two;
   - shift/add or addition-chain plans for composite constants;
   - the existing repeated-add sequence as a conservative fallback;
   - a runtime helper only when its full call/setup cost wins and its effects
     are legal at the site.
3. Compute the scaled value at full index width, then add it to the base once.
   Preserve 16-bit wrap and carry across page boundaries.
4. Keep the choice local to encoding the explicit `AdvanceAddress` operation;
   do not run an instruction-text peephole over unrelated instructions.
5. Use byte and cycle costs to retain the repeated-add fallback whenever the
   binary plan does not improve both dimensions.

For scale twelve, an acceptable plan is equivalent to `index * (8 + 4)` or
`(index * 3) << 2`; it must not emit twelve full word additions.

### Tests

- Exhaustively compare generated scale calculations with a 16-bit reference
  for every byte index and representative word indexes.
- Cover scales 1, 2, 3, 4, 5, 12, 16, 31, and 255.
- Exercise bases whose low byte forces a carry and cases that wrap at `$FFFF`.
- Keep existing scale-two Y-carrier and affine static-array selections green;
  the general planner must not displace a cheaper specialized mode.
- Add cost tests demonstrating that a rejected plan retains the fallback.

### Acceptance criteria

- Scale twelve no longer emits twelve repeated pointer additions.
- Address formation remains correct for the full representable index range,
  not only the motivating table's four valid indexes.
- Specialized unit/scale-two addressing remains no worse in bytes or cycles.
- The selector has no dependency on record names, fields, or array bounds.

### Suggested commit

```text
mir6502: strength reduce constant indexed-address scales
```

## Slice 4: narrow discarded-high constant products

### Goal

Turn a word constant multiplication whose only observable result is an explicit
byte truncation into a byte multiplication, allowing the existing byte
constant-strength reducer to emit only the required low-lane shifts.

The motivating shape is:

```text
v1 =.w #$20 mul v0
v2 =.b truncate v1 from.w
store.b destination, v2
```

The selected shape is equivalent to:

```text
v2 =.b v0 lsh #$05
store.b destination, v2
```

### Implementation

1. Add an analyzed pre-home rewrite before
   `strength_reduce_constant_multiplications` expands the word operation.
2. Require an exact reaching definition for the word product and prove that:
   - every result use observes only the low lane through byte truncation or an
     equivalent proven low-lane projection;
   - the synthetic high lane is dead across the routine and terminator;
   - narrowing does not remove or duplicate an observable operand read;
   - no call, compare, word store, block argument, or machine operation consumes
     the complete product.
3. Initially admit byte-derived operands and power-of-two constants. Broaden to
   other constants only after the runtime-helper cost and result-lane contract
   are covered.
4. Replace the word product plus truncation with a byte product and let the
   existing `strength_reduce_byte_multiply` path select `Lsh`/`ASL`.
5. Declare the exact flag changes of the replacement and reject the rewrite if
   any removed word-chain flags are live.
6. Record applied and blocked reasons, especially high-lane-live,
   multiple-reaching-definitions, observable-source-read, and flags-live.

### Tests

- Exhaustively validate `(constant * value) & $FF` for every byte value with
  constants 2, 4, 32, and 128.
- Negative cases where the word result is also returned, compared, passed to a
  call, stored as a word, or consumed on another CFG path.
- A volatile byte operand must still be read exactly once.
- Pointer-cell and unknown-width operands retain the word fallback unless their
  complete evaluation has already been staged safely.
- Signed-looking low-byte values must retain modulo-256 behavior without
  introducing a signedness assumption.

### Acceptance criteria

- Each motivating multiply-by-32 emits one byte load, five `ASL`s, and one byte
  store, with no high-lane home or `ADC` chain.
- All four expressions together have the same results for every possible
  harmonic byte.
- Full-word consumers remain byte-for-byte on the existing word path.
- The rewrite is driven by typed MIR uses and liveness, not local source syntax.

### Suggested commit

```text
mir6502: narrow constant products with dead high lanes
```

## Slice 5: measurement and compact-copy decision gate

### Goal

Measure the combined required slices and decide whether eliminating the
per-lane staging homes is worth a separate implementation.

### Required work

1. Rebuild `unlimited-bobs.act` with standalone MIR6502 output and record:
   - `SelectEffect` byte range;
   - record-copy byte count;
   - multiply/truncate byte count;
   - number of pointer preparations and scaled additions;
   - generated zero-page and spill homes;
   - full XEX size.
2. Compare runtime behavior for all four effects; this is a semantic smoke test,
   not a timing benchmark for a cold routine.
3. Sweep other indexed record-copy fixtures and sample programs to ensure the
   optimization is not isolated to the motivating case.
4. Update this document with the measured before/after table and mark Slices
   1-4 complete.

### Gate for a later compact-copy slice

Do not add a new stack-staged operation merely to approach the Mad Pascal byte
count. Add a follow-up only if measurements show material staging still causes
material code size or zero-page/spill pressure in ordinary programs.

If justified, introduce a bounded target operation such as
`CopyIndirectBytesToDirectRange` with these minimum rules:

- a small explicit maximum extent justified by the compiler's stack policy;
- all source bytes pushed before any destination write;
- balanced stack on every path;
- reverse pop/store order mapped to the correct destination offsets;
- nonvolatile endpoints initially;
- exact A/Y/flag, stack, indirect-read, and direct-write effects;
- transactional post-home selection with a positive cost win;
- self-copy and both overlap directions tested exhaustively.

Statically disjoint direct ranges may instead use a directional indexed loop.
Unknown pointer ranges must retain overlap-safe staging.

### Acceptance criteria

- Combined required slices reduce the motivating routine to well below 500
  bytes without weakening record semantics. This is a release measurement, not
  a unit-test constant.
- No required slice increases hot-loop code in the unlimited-bobs renderer.
- Any compact-copy follow-up is supported by measurements beyond this one
  routine.

### Suggested commit

```text
docs: record aggregate-copy optimization results
```

## Required validation after every implementation slice

Run focused checks first:

```sh
cargo test mir6502_fixtures_match_snapshots
cargo run --bin actionc-mir6502-sweep -- --materialize fixtures/mir6502
cargo test --manifest-path tools/vm-runtime-tests/Cargo.toml \
  record_assignments_execute_in_all_public_modes
```

Because this work changes the NIR-to-MIR boundary and MIR verifier/printer
coverage, also run the repository-required NIR checks even though the intended
NIR text is unchanged:

```sh
cargo test nir_fixtures_match_snapshots
cargo run --bin actionc-nir-sweep -- fixtures/nir
cargo test
```

Before closing Slice 5, additionally compile all samples and the motivating
program through the public standalone path:

```sh
cargo test --test samples
cargo run --bin actionc -- \
  --mode mir6502 \
  --runtime standalone \
  --listing /tmp/unlimited-bobs.lst \
  -o /tmp/unlimited-bobs.xex \
  samples/demoscene/unlimited-bobs.act
```

Fixture changes must be classified explicitly as one of:

- intentional pre-home MIR contract change from retaining `CopyBytes`;
- intentional target-strategy improvement in materialized MIR;
- printer-only change; or
- bug fix.

## Completion criteria

This plan is complete when:

- initial MIR retains verified aggregate-copy identity;
- post-home MIR contains no unresolved aggregate-copy pseudo operation;
- indexed aggregate copies prepare each endpoint once;
- scale-twelve address formation uses a costed strength-reduced plan;
- dead-high multiply/truncate shapes use byte-width computation;
- arbitrary overlap, self-copy, volatile ordering, page crossing, and full-range
  arithmetic tests pass;
- the full test suite and both IR sweeps pass;
- the measured `SelectEffect` routine is below the stated gate without a
  source-level workaround; and
- the relevant MIR6502 and record-assignment contract documents describe the
  final selected and fallback strategies.
